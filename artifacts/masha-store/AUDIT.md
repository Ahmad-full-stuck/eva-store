# مراجعة ماشا متعددة الأدوار

هذه قوائم مراجعة هندسية وليست ادعاءً بأن وكلاء مستقلين أو اختبارات إنتاجية قد نُفذت.

## ناقد التصميم وتجربة المستخدم
- اختبر 320 و375 و768 و1440 بكسل، قص الصور، تباين النص، لوحة المقاسات وسهولة الاستخدام بلوحة المفاتيح.
- استبدل صور العرض بصور ماشا الحقيقية، وأضف وصفًا بديلًا دقيقًا لكل صورة.

## مهندس التجارة
- لا تعرض المخزون أو رسوم الشحن كحقائق قبل التأكيد.
- اجعل المقاس واللون variants مستقلة لكل منتج بمخزون مستقل.
- حالات الطلب: received, confirmed, preparing, shipped, delivered, cancelled, returned.
- احسب السعر والمخزون على الخادم، ولا تثق بإجمالي يرسله المتصفح.

## مهندس قاعدة البيانات
- localStorage ليس مصدر حقيقة للطلبات أو المخزون.
- استخدم قاعدة منفصلة لماشا لا قاعدة إيفا. مخطط SQL المقترح في docs/schema.sql.
- الأسعار أعداد صحيحة بالدينار؛ استخدم قيود تحقق وفهارس ومعاملة لإنشاء الطلب وتحديث المخزون.
- خزّن رابط إنستغرام كوسيط اختياري وليس رابط MP4.

## مراجع الأمن
- الواجهة الحالية عرض أولي ولا تحتوي لوحة إدارة محمية أو backend إنتاجيًا.
- قبل الإطلاق: مصادقة وصلاحيات على الخادم، rate limiting، validation، حماية من الطلبات المكررة، سجلات لا تكشف بيانات العملاء، ونسخ احتياطي.
- لا تضع أسرارًا أو مفاتيح VAPID خاصة في Git أو frontend. لا تستخدم قاعدة إيفا مع ماشا.

## SEO والأداء
- بعد اختيار النطاق، أكمل canonical وOpen Graph وsitemap وrobots.
- أضف روابط ثابتة للمنتجات وProduct structured data، وصور WebP/AVIF مناسبة.
- أضف سياسات خصوصية وتوصيل واسترجاع معتمدة من المتجر.
